# Document Indexer · AI Advent, день 21

Локальный семантический поиск по Markdown, TXT и текстовым PDF. Один корпус индексируется двумя способами: фиксированными токенными окнами и по структуре документа. Русский интерфейс позволяет сравнить границы чанков, результаты поиска и метрики на размеченных вопросах.

## Текущее состояние

Реализованы загрузка и нормализация, обе стратегии chunking, интеграция E5, SQLite, CLI, пять экранов Streamlit, фоновые задания, оценка и экспорт отчётов.

Проверено: установка, CLI `--help`, статистика реального корпуса, **27 автоматических тестов** без скачивания модели, включая навигацию Streamlit. Отдельный smoke test с настоящей моделью подготовлен.

**На момент публикации полный прогон индексации, поиска и оценки с настоящей моделью ещё не проверен. Метрики качества и скорости пока не получены.** Визуальная проверка в браузере также не выполнена: инструмент браузера не запустился из-за ошибки конфигурации среды. Это рабочая версия учебного проекта, а не завершённый итог эксперимента.

## Установка на Windows

Нужен Python 3.11. Активация `Activate.ps1` не требуется.

```powershell
git clone https://github.com/MariaAgafonova/advent-day-21-document-indexer.git
cd advent-day-21-document-indexer
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -e ".[dev,corpus]"
```

Если Python 3.11 отсутствует, окружение можно создать через `uv`:

```powershell
python -m pip install uv
python -m uv venv --python 3.11 .venv
python -m uv pip install --python .venv/Scripts/python.exe torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
python -m uv pip install --python .venv/Scripts/python.exe -e ".[dev,corpus]"
```

В проверенной среде использовались Python 3.11.16, sentence-transformers 3.4.1, transformers 4.57.6, NumPy 2.4.6, PyMuPDF 1.28.2, Streamlit 1.64.0. PyTorch 2.14.1 CPU в этой Windows-среде выдавал ошибку `c10.dll`; установлен PyTorch 2.6.0 CPU.

## Корпус

Добавьте свои файлы через интерфейс или в `data/raw`. Загрузка официальных Android-материалов — отдельная операция:

```powershell
.\.venv\Scripts\python.exe scripts/download_corpus.py
.\.venv\Scripts\python.exe scripts/prepare_evaluation.py
.\.venv\Scripts\python.exe -m document_indexer inspect --input data/raw --output output/corpus_stats.json
```

Скрипт скачивает шесть материалов Android Developers: lifecycle, ViewModel, coroutines, WorkManager, deep links и архитектура. Существующие файлы не перезаписываются. URL, дата получения, язык и атрибуция записываются в `data/sources.json`. Материалы принадлежат их авторам; текст распространяется на условиях CC BY 4.0, примеры кода — Apache 2.0 согласно условиям Android Developers.

Фактический первоначальный локальный снимок: **6 файлов, 13 997 слов, 34,99 условной страницы**, без ошибок, пустых файлов и дубликатов. Это результат `inspect`, а не фиктивные данные. После обновления источников или очистки служебных заголовков число слов и хеши могут измениться. Актуальные значения всегда проверяйте командой `inspect`. Слова считаются регулярным выражением по нормализованному тексту, включая Markdown и код; 400 слов соответствуют условной странице. Дубликаты исключаются из проверки достаточности объёма.

Скачанные документы, модель, локальные базы и пользовательские файлы не входят в Git. Индексация читает только локальные документы. При первом обращении E5 скачивается из Hugging Face, затем вычисления выполняются локально. `inspect --tokens` дополнительно считает токены и требует доступную модель.

## Запуск интерфейса

```powershell
.\.venv\Scripts\python.exe -m streamlit run ui/app.py
```

Откройте <http://localhost:8501>.

- **Документы** — несколько файлов за раз, до 20 МБ каждый; статистика, ошибки извлечения, просмотр нормализованного текста. Совпадающие имена получают суффикс.
- **Индексация** — настройки размера/overlap, явная кнопка построения двух индексов, отдельные статусы и реальные счётчики обработки.
- **Чанки** — две стратегии рядом, диапазоны в сохранённом исходнике, overlap, границы разделов, соседи и пересечения другой стратегии. Метаданные раскрываются; вектор показывается по запросу.
- **Поиск** — один вопрос к двум индексам, top-k, фильтр документа, similarity и время; переход к источнику или чанку.
- **Сравнение** — проверка разметки и совместимости, Hit@1/Hit@5/MRR@5, размеры и время, разбор каждого вопроса, экспорт JSON/CSV/Markdown.

## CLI

```powershell
.\.venv\Scripts\python.exe -m document_indexer --help
.\.venv\Scripts\python.exe -m document_indexer index --input data/raw --strategy fixed --output output/fixed.sqlite
.\.venv\Scripts\python.exe -m document_indexer index --input data/raw --strategy structural --output output/structural.sqlite
.\.venv\Scripts\python.exe -m document_indexer search --index output/structural.sqlite --query "Как выполнять фоновые задачи?" --top-k 5
.\.venv\Scripts\python.exe -m document_indexer compare --fixed output/fixed.sqlite --structural output/structural.sqlite --questions data/evaluation.json --output output/comparison
```

После каждой команды `index` процесс завершается; `search` читает сохранённую SQLite и не кодирует документы заново. Для индексации доступны `--chunk-size`, `--overlap`, `--device`. У `compare` есть `--repeats` (по умолчанию 3).

## Правила разбиения и хранения

Текст нормализуется в LF с удалением NUL, сохранением абзацев, заголовков и отступов. UTF-8/BOM читается строго. PDF извлекается постранично; пустые страницы вызывают предупреждение о возможной необходимости OCR. Для PDF структурная единица — страница, распознавание визуальных заголовков не выполняется.

`fixed`: окна по 300 токенов со сдвигом 250, overlap 50. Используется fast tokenizer и offset mapping; текст берётся срезом исходника, не через `decode`. Последнее окно сохраняет конец документа; разные файлы не смешиваются.

`structural`: Markdown-разделы и абзацы объединяются до 300 токенов внутри одного раздела. Заголовки в fenced code игнорируются. Небольшой блок кода сохраняется целиком; слишком большой блок разбивается окнами с overlap 50. Обычные структурные чанки не перекрываются. TXT имеет один исходный раздел.

Диапазоны символов — `[start_char, end_char)` в нормализованном тексте; строки и страницы с единицы. Чанк содержит `chunk_id`, `strategy`, `source`, `source_url`, `title`, `sections`, `ordinal`, `text`, диапазоны символов/строк/страниц, `token_count`, `content_hash`. ID — SHA-256 пути, хеша документа, стратегии, настроек, диапазона и текста. Fixed хранит все пересекаемые разделы.

Обе стратегии используют `intfloat/multilingual-e5-small`, `passage: ` для документов, `query: ` для запросов и `normalize_embeddings=True`. Метаданные в embedding-вход не добавляются. Полный вход со специальными токенами проверяется до кодирования; превышение лимита вызывает ошибку, незаметное truncation запрещено. По умолчанию CPU и batch size 16.

SQLite содержит `index_config`, `documents`, `chunks`. Конфигурация хранит схему, build ID, хеш корпуса, модель и фактическую revision, размерность, dtype, настройки и версии зависимостей. Векторы — little-endian float32 BLOB; при чтении проверяются длина, размерность, конечность и нормы. Новая база проверяется во временном файле и атомарно заменяет прежнюю. Нормализованный снимок документов сохраняется внутри базы. Рядом экспортируются JSONL чанков и файл измеренного времени сборки.

Поиск вычисляет `matrix @ query_vector`; сортировка по убыванию similarity, при равенстве — по `chunk_id`. Similarity не является вероятностью или процентом уверенности.

## Разметка и оценка

`scripts/prepare_evaluation.py` содержит 18 заранее составленных русских вопросов к английскому корпусу. Эталон выбирается по фиксированному абзацу источника, без доступа к поиску или chunk ID. При изменении материалов скрипт может потребовать проверки anchors. Разметку нужно подготовить до первого просмотра результатов поиска.

Формат `data/evaluation.json`:

```json
{
  "questions": [{
    "id": "q01",
    "question": "Вопрос по документу",
    "answers": [{
      "source": "document.md",
      "document_hash": "SHA-256 нормализованного текста",
      "start_char": 0,
      "end_char": 5,
      "answer_excerpt": "Текст"
    }]
  }]
}
```

Это пример схемы, не готовая разметка. Проверяются хеш, диапазон и точное совпадение excerpt. Релевантен чанк, целиком содержащий хотя бы один эталонный диапазон. Hit@1/Hit@5 — доля вопросов с релевантным ответом в соответствующем top-k; MRR@5 — средний обратный ранг первого релевантного результата, при отсутствии в top-5 — ноль.

Измерения выполняются после прогрева с повторениями и чередованием порядка стратегий. Сохраняются median/p95 кодирования запроса и ранжирования; загрузка модели учитывается отдельно. JSON содержит подробные результаты и настройки, CSV — позиции по вопросам, Markdown — метрики и таблицу вопросов. **Сравнительных чисел в этом репозитории пока нет: реальный эксперимент ещё предстоит завершить.**

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pytest -m integration -q
```

Первый запуск не скачивает модель. Проверяются кодировки, PDF-страницы, заголовки/код, границы/overlap/хвосты, стабильность ID, BLOB и атомарная запись, ранжирование, метрики, устаревшая разметка, загрузка файлов, задания, HTML escaping и отсутствие повторной индексации при навигации. Второй запуск требует настоящую E5 и проверяет обе стратегии с сохранением и поиском.

## Ограничения

- Нет OCR, LLM-генерации, MCP, авторизации и облачного развёртывания.
- Модель нужно первоначально скачать; PDF с изображениями без текста не распознаются.
- Задания переживают rerun Streamlit в пределах процесса; после остановки сервера их нужно запустить заново. Сохранённые базы остаются доступны.
- Поиск использует матрицу NumPy в памяти: это учебный объём, не распределённая система.
- README фиксирует промежуточное состояние. Настоящий integration smoke, замеры и полный пользовательский сценарий ещё не подтверждены.

## Сценарий демонстрации на 3–5 минут

До демонстрации завершите скачивание модели, постройте оба индекса и запустите оценку. Эти шаги пока требуют фактической проверки.

1. «Документы»: показать реальный объём и текст одного Android-материала.
2. «Индексация»: объяснить 300/50 и различие правил; показать статусы сохранённых индексов.
3. «Чанки»: выбрать один документ, сравнить границы и overlap, показать пересекающиеся диапазоны.
4. «Поиск»: задать одинаковый вопрос, открыть найденный источник и чанк.
5. «Сравнение»: разобрать один эталон, объяснить Hit/MRR, скачать отчёт и сделать вывод только по измеренным данным.
